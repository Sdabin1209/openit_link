# 선언된 HTTP 계약을 생산 경계에서 검증한다

## 상태
채택.

## 맥락
경로에 붙인 선택적인 응답 스키마만 검사하면 상태 코드·필수 머리글·매체·스칼라·생성 오류가 검사 밖에 남는다.
빈 역할 집합은 공개 경로인지 설정 누락인지 구분되지 않았다.

## 결정
서비스 식별자로 boundary-contracts의 HttpContract를 연결한다. wiring이 역할·한도의 타입화된 바인딩을 준다.
시작 시 경로 선언과 역할·한도를 대조한다. 요청과 최종 직렬화된 응답을 계약으로 검사한다.
인증 경로에서 빈 역할 집합은 접근을 허용하지 않는다. 익명 허용은 계약에 명시된 조건만 따른다.

## 왜
OpenAPI 3.1의 HTTP 계약과 JSON Schema 데이터 정의를 그대로 사용하면 선택적인 검사 누락과 정의 복사를 줄인다.
WSGI(PEP 3333) 서버 구조를 유지하면서 생산자가 자기 출력을 책임진다(R7).

## 검토한 대안
핸들러별 수기 검사는 오류·미디어 경로가 빠질 수 있다. 구현에서 계약을 생성하면 독립 검토가 어렵다.

## 결과
잘못된 출력은 503으로 차단한다. 이미 시작된 스트림의 업무 이벤트 검증은 그 이벤트 생산자가 맡는다.
계약을 연결하지 않은 라이브러리 사용자의 호환 API는 유지하며 서비스 영역의 wiring에서 연결을 요구한다.

## 되돌리는 조건
동일한 생산자 검증과 독립적인 계약 검토를 제공하는 통신 기반으로 대체할 때 새 ADR을 쓴다.
